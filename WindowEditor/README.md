# WindowEditor — редактор окон и балконных блоков для Revit

WPF-редактор схемы окна в духе Renga. Схема хранится как JSON в параметре типа
`WE_Config`, по ней надстройка перегенерирует семейство окна и загружает его в
проект с перезаписью. Окна в группах обновляются без входа в группу.

## Сборка и установка

Нужны Windows и .NET 8 SDK (или Visual Studio 2022).

```
dotnet build -c Release -p:RevitVersion=2025
```

`RevitVersion`: 2023, 2024 (.NET Framework 4.8), 2025, 2026 (.NET 8).
Ссылки на Revit API — из NuGet (Nice3point.Revit.Api.*).

1. `WindowEditor.addin` → `%AppData%\Autodesk\Revit\Addins\2025\`
2. `WindowEditor.dll` (и для 2023/2024 — `System.Text.Json.dll` с зависимостями) → `%AppData%\Autodesk\Revit\Addins\2025\WindowEditor\`

Вкладка «Окна»: «Редактировать окно», «Новое окно». При первом запуске
надстройка спросит шаблон окна и найдёт (или спросит) шаблон «Типовая модель».

## Что умеет

**Схема (вкладка «Схема»)**
- Секции: блок из нескольких рам в ряд. Балконный блок = дверная секция от пола +
  оконная секция, поднятая на высоту подоконной части стены («Низ проёма над низшим»).
- Импосты: V / H, удаление Del, перетаскивание с шагом 5 мм или точное значение.
- Заполнения: глухое, поворотная, поворотно-откидная, откидная, дверная
  поворотная и поворотно-откидная (дверь — тоже створка).
- Стёкла пронумерованы на схеме — номер нужен для материала.

**Створка с полями.** «Импост в створке» (Shift+V / Shift+H) делит заполнение
створки, а створка остаётся одной: дверь со стеклом сверху и панелью снизу,
створка во всю высоту витража. Импост створки — `SashMullionWidth`, линии открывания
строятся по всей створке, у каждого поля свой материал.
Каждое поле — «Стекло» или «Панель (глухая)»: панель строится своей толщиной
(`PanelThickness`), в подкатегории `WE_Панель`, не входит в площадь остекления и
считается в `WE_Площадь панелей`. Шаблоны: «Балк 1» (два стекла), «Балк 1 — низ панель».

**Г- и Т-образная рама.** Заполнение ячейки «Стена (вне рамы)»: рама обходит её
контур, импост на границе становится брусом рамы. Так делаются балконные блоки
с общей фрамугой над дверью и окном (121 Балк, 1111 Балк, Центр 1223). Проём,
подоконники и откос торца подоконной части считаются по этому контуру; под
дверью подоконник и отлив не ставятся. «Зазор над стеной» — зазор под окном.

**Отражение и имя.** «⇋ Отразить Л/П» зеркалит схему, стороны петель и откосы,
меняет в имени Левое ↔ Правое и 212л ↔ 212п. «Имя по схеме» подставляет код:
ряды снизу вверх, в каждом — число створок и глухих полей, у которых там низ
(створка с полями — одна). Пример: 121, 212, 1223. Код заменяет первое число в
имени («v3» числом не считается).

**Шаблоны** — по каталогу pmN.Окно v3: 1, 11, 111, 2, 12, 21, 22, 121, 3, 31,
4, 41, 44, 24, 212п, Балк 1/2/21/32, 121/1111/1112/122 Балк Правое, Балк Центр 1223.
Левые варианты — кнопкой «Отразить».

**Пустой проём.** Флажок «Пустой проём (без рамы)» или шаблон «Пустой проём»:
рама, створки и стёкла не строятся, размеры секции — размеры проёма, зазоры не
действуют. Откосы по граням, подоконные доски и отливы включаются и выключаются
на вкладке «Комплектация» как у окна; доска и отлив лежат на низе проёма, откосы
делятся по плоскости «Рама от наружной грани». Г-образный пустой проём — двумя
секциями с разной отметкой низа. При переключении режима размер проёма сохраняется.

**Проём (вкладка «Проём»)**
- Толщина стены, сторона фасада.
- Положение рамы по глубине: привязка (от наружной грани, от четверти, по оси
  стены, от внутренней грани) и смещение вглубь (+) / наружу (−), кнопками ◀ ▶
  по 10 мм (с Shift — по 50) или числом. Смена привязки раму не двигает — меняется
  только отсчёт. Схема разреза у откоса показывает стену, четверть, раму, откосы
  и расстояния до граней. Откосы, подоконник и отлив подстраиваются под раму.
- Монтажные зазоры: боковой и верхний общие, нижний — у каждой секции.
- Четверти: боковая, верхняя, глубина. Проём вырезается двумя пустотами —
  широкой за четвертью и узкой в наружном слое. Показывается заход рамы за четверть.
- Г- и П-образные проёмы балконных блоков вырезаются по фактическому контуру,
  подоконная часть стены остаётся.

**Комплектация (вкладка «Комплектация»)** — вложенные общие семейства
- Подоконник внутренний — у каждой секции: толщина, вынос, заход под раму, заход в стену.
- Снаружи у каждой секции: нет / отлив / подоконник — переключается, настройки
  обоих сохраняются.
- Откосы: каждая грань проёма отдельно, внутренний и наружный независимо.
  Грани находятся сами: Левый, Правый, Верх, у балконных блоков — «Ступень низ»
  (торец подоконной части у двери), при разной высоте секций — «Ступень верх».
- Заход подоконника в стену делается только там, где сбоку стена: у двери его нет.

**Материалы (вкладка «Материалы»)**
- Рама, створки, каждое стекло, каждый подоконник/отлив, каждая грань откоса.
- В семействе это параметры типа `WE_Мат. …`, их можно менять и в проекте —
  редактор при следующем открытии подхватит изменения.
- Материалы ищутся по имени: если в проекте есть одноимённый, используется он.

## Угловые окна (наружный угол 90°)

Два окна в двух стенах + угловой узел.
1. В каждом окне: «Проём» → «Угол здания»: угловая сторона (слева/справа с фасада),
   «Ведущее окно угла» — ровно у одного, «Угловой соединитель» — реальный размер,
   материал соединителя — на вкладке «Материалы». У угловой стороны нет зазора,
   четверти и откоса; рама кончается у соединителя (рама от наружной грани +
   соединитель), проём доходит до угла здания.
2. Стыки: подоконник, отлив/наружная доска и верхние откосы ведущего окна проходят
   до угла и закрывают угловой квадрат; у второго окна они примыкают к ним. Условие —
   у обоих окон одинаковые толщина стены и положение рамы (проверяется).
3. Кнопка «Угловое окно»: выберите два окна. Команда проверит стены (90°, наружный
   угол), стороны, ведущее окно, высоты, толщины и положение рамы; придвинет окна к
   углу; поставит семейство «WE_Угловой узел …» (обобщённая модель: стойка-соединитель
   + пустота) и вырежет угловой квадрат обеих стен на высоту проёма. Повторный запуск
   заменяет узел. Соединитель идёт в спецификацию с «WE_Вид элемента» = «Угловой
   соединитель».
4. Угловой пустой проём — так же, с флажком «Пустой проём»: узел без стойки, только
   вырез угла.

Если окна в группе, узел нужно добавить в группу вручную — команда напомнит.

## Отзеркаленные окна

Окна нельзя зеркалить: схема открывания и марка перестают соответствовать модели.
- При «Редактировать окно» надстройка проверяет все экземпляры семейства.
- Кнопка «Проверить окна» проверяет всю модель.

Находятся отзеркаленные экземпляры (инструмент «Зеркально» и стрелки «Отразить»
определяются одинаково — по отражению в матрице экземпляра) и окна, у которых
наружная сторона семейства смотрит в помещение (для окон редактора). Можно
исправить их одним действием (окна в группах не трогаются — они выделяются),
выделить и выйти или продолжить. Левый вариант делается отдельным семейством
кнопкой «Отразить Л/П».

## Спецификации

Окно (параметры типа, общие): `WE_Схема открывания`, `WE_Количество створок`,
`WE_Количество дверных створок`, `WE_Количество глухих`, `WE_Площадь остекления`, `WE_Площадь панелей`,
`WE_Площадь окна`, `WE_Длина импостов`, `WE_Ширина/Высота блока`,
`WE_Ширина/Высота проёма`. «Ширина»/«Высота» семейства = размер проёма.

Комплектация — категория «Обобщённые модели», семейство «WE_Элемент окна»
(параметры экземпляра, общие): `WE_Вид элемента` (Подоконник внутренний, Отлив,
Подоконник наружный, Откос внутренний, Откос наружный), `WE_Расположение`
(секция или грань), `WE_Длина/Ширина/Толщина элемента`, материал.

ФОП создаётся сам: `%AppData%\WindowEditor\WindowEditor_SharedParams.txt`.
GUID параметров фиксированы в `WindowParams.cs`.

## Вложенное семейство «WE_Элемент окна»

Создаётся один раз в `%AppData%\WindowEditor\WE_Элемент окна.rfa` — параметрический
брусок. Его можно заменить своим (например, с профилем подоконника), если соблюдать
соглашение: начало координат в углу, тело в X∈[0;`WE_Размер X`], Y∈[0;`WE_Размер Y`],
Z∈[0;`WE_Размер Z`], параметры экземпляра `WE_Размер X/Y/Z`, `WE_Материал`
и общие параметры элемента; семейство общее (Shared), не на рабочей плоскости.

## Проверить на первом окне

- **Сторона фасада.** Для окон без конфигурации берётся по стене. Если рама и
  отлив оказались со стороны помещения — снимите/поставьте «Фасад со стороны +Y».
- **Низ проёма.** Ищется опорная плоскость «Sill» / «Подоконник» / «Низ», иначе
  низ = 0 семейства. У балконного блока «Высота нижнего бруса» экземпляра должна
  быть 0 (низ двери).
- **Вырез четверти.** Толщина стены-основы в семействе подгоняется под настройку;
  если в проекте четверть не вырезалась, проверьте, что пустоты пересекают стену.
- **Имя семейства.** При сохранении под новым именем одноимённое семейство в
  проекте будет перезаписано.

## Устройство кода

| Файл | Назначение |
|---|---|
| `Model/WindowConfig.cs` | JSON-модель: секции, ячейки, зазоры, четверти, комплектация, материалы; миграция v1 |
| `Model/WindowLayout.cs` | Раскладка рамы секции: единицы, поля, импосты, контур рамы; операции |
| `Model/Mirror.cs` | Отражение схемы, имя Л/П, код в имени |
| `Model/Presets.cs` | Шаблоны схем |
| `Model/WindowGeometry.cs` | Контур проёма, грани откосов, подоконники/отливы/откосы, стёкла, слоты материалов |
| `UI/EditorWindow.*` | WPF-редактор |
| `RevitSide/WindowFamilyBuilder.cs` | Генерация семейства окна |
| `RevitSide/AccessoryFamily.cs` | Создание и загрузка вложенного семейства |
| `RevitSide/WindowParams.cs` | Общие параметры, единицы |
| `RevitSide/Commands.cs` | Команды, загрузка в проект |
